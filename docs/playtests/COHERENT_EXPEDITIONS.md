# Coherent expedition human review

Status: protocol prepared; human participants and a physical Quest 3 are not
available in the development environment. Automated agents, desktop captures and
WebXR emulation do not answer the questions below.

Use a release build and record its commit, seed, platform, input device, guidance
setting and date. Recruit one person new to the game and one experienced player.
Each plays two different ships for 20–30 minutes each, with a short break. Use
Guided for the newcomer and Off for the experienced player. Counterbalance ship
order: seed 713 (machines) and 27 (vents), with seed 7 (conduits) as a third
condition check. Start fresh characters; do not import earned inspection scenes.

Observe without explaining the solution. Record timestamps for boarding, the
first landmark noticed, first chosen detour, first reward used, first understood
warning, first guardian attempt, recovery and any voluntarily revisited location.
Record deaths, navigation stalls longer than ten seconds, menu confusion and
abandoned goals. After the first guardian, let the participant decide whether to
continue. Use an explicitly earned late-game checkpoint only in a separate
five-minute branch/rig usability session, never as evidence of the fresh opening.

After each ship, ask these six questions:

1. What was the ship's local problem, and what could you do about it?
2. What warned you that the floor or enemy was about to become dangerous?
3. Which reward changed what you did in a later fight?
4. What changed because of an earlier decision? What evidence connected the two?
5. Did a failed fight suggest a different approach? Did recovery make retrying appealing?
6. What would you try differently on another ship, and would you choose to play it?

Record the participant's words, observed actions and investigator interpretation
separately. A recalled label alone is not evidence that a rule was understood.
Compare whether the second ship prompts a different route, preparation or combat
decision; do not score a fast completion as enjoyment.

For local co-op, add a separate session with one player exploring another deck
while the other enters shelter or a guardian fight. Check shared consequences,
personal purchases, marks/targets, refit previews, split-screen readability and
rejoining after a save. The automated separated-party run is a correctness check,
not a substitute for two people judging the experience.

On a physical Quest 3, use the [device checklist](QUEST3_CHECKLIST.md), then repeat
the cold-floor warning and one new guardian. Record actual headset frame rate,
controller response, legibility, brightness and discomfort. Stop if the player
feels unwell. Linux/Windows graphics, physical gamepads and mobile Safari also
need real-device confirmation; the release report lists exactly which automated
and native environments ran.
